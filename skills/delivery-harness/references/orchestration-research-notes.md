# Runtime Capability Research

Research the currently exposed native interface only when a required capability is unclear. `runtime-adapters.md` is the single execution contract; there is no provider registry, fixed model catalog or bundled native workflow runner.

A node is eligible on the current host exactly when its `allowed_providers` includes that host. `preferred_provider` is advisory ordering among allowed hosts and never blocks an otherwise allowed current host. Provider identity is not capability evidence or permission to bridge to another runtime.

Observe launch identity, fresh context, instructions, workspace binding, permission inheritance, terminal results, capacity, cancellation and resume behavior. Resolve deferred tools where available. A package or flag alone proves none of these. Record sources, actual interface and observed limits in existing RUN evidence rather than introducing another registry.

Use the host's current tool descriptions and local help first, and authoritative documentation when needed. Do not assume a version number proves a feature. Do not probe another host or install software to replace a missing surface without explicit instruction.

Models and role routing stay with the host unless the user explicitly selects supported options. Prefer events or cursor waits to polling. Test browser access inside the actual reviewer. Keep graph state, exact authorization, leases and Git verification in the Harness parent; native cached completion never substitutes for current evidence.

The two-way project-size gate keeps small work direct. There is no cross-host preflight, no bridged process, and no declared fallback that grants another host. Ineligible work is blocked on provider mismatch rather than probing or launching the other runtime.
