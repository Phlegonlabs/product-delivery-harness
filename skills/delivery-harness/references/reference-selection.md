# Reference Selection

The optional [reference catalog](option-library/README.md) is a maintained source of comparison material. It is not a stack, dependency, provider choice, approval gate, runtime, or second delivery workflow.

Use it only when a real choice is unresolved or an adopted decision needs scoped implementation, review, or activation context. Start from the need, current approved decisions, constraints, and existing implementation. Read only the relevant domain files; do not load the catalog for every invocation. When comparing options, present coherent alternatives and keep a healthy existing stack as a valid option. No catalog name is a mandatory vendor: CSS/Tailwind, icon systems, Cloudflare, Expo/React Native, GSAP, or any other reference is optional, and simple CSS/WAAPI remains possible.

For an unresolved decision, record the candidate, fit and avoid conditions, alternatives considered, source and check date, applicable constraint, and the chosen outcome in the existing stack decisions, architecture, PRD, or UI Design Brief. Do not create a new mandatory register, schema, gate, or checklist. Existing decisions stay in force until an actual change reopens the decision for its owner.

Refresh an official source only when needed for an actual recommendation or volatile claim, and follow the existing research-disclosure boundary. Do not search randomly on every run. Reference updates do not retroactively reopen approvals or change frozen inputs. Catalog records never grant installation, network, runtime, subagent, deployment, publishing, or other execution authority; security rules and existing project contracts remain binding.

Keep product runtime, product agent runtime, and the current development runtime separate. The catalog supplies context; only adopted project obligations determine applicable implementation and verification work.
